## Задание 4.1 — подсчёт инверсий

Инверсия — пара исходных позиций `i < j`, для которой `A[i] > A[j]`. Обычная проверка всех пар требует `O(n²)`. В `src/task4_1.cpp` массив делится пополам, для каждой половины инверсии считаются рекурсивно, затем при слиянии отсортированных половин считаются **перекрёстные** инверсии. Если правый элемент меньше текущего левого, он меньше **всех ещё не перенесённых элементов левой половины**; к ответу прибавляется `middle - i`. Равные элементы инверсией не считаются, поэтому сравнение использует `<=`.

Время `O(n log n)`, память `O(n)` на один вспомогательный массив плюс `O(log n)` на стек рекурсии. При `n = 10^6` максимальный ответ равен `n(n-1)/2 ≈ 5·10^11`, поэтому счётчик имеет 64-битный тип `std::int64_t`, а не `int`.

## Задание 4.2 — Merge Sort массива с одним буфером

`src/task4_2.cpp` выделяет **один** буфер размера `n` до рекурсии и передаёт его во все вызовы. Половины сортируются рекурсивно и сливаются в буфер, затем результат копируется обратно. Если `a[middle-1] <= a[middle]`, обе отсортированные половины уже вместе упорядочены, и слияние пропускается.

Для отрезков длиной не более `32` используется сортировка вставками. Её цена на маленьком отрезке `O(B²)`, но у неё низкие накладные расходы; для большого массива время остаётся `O(n log n)`, поскольку `B=32` — константа. **Универсального оптимального порога нет:** он зависит от процессора, компилятора, типа данных и их распределения. `32` — практическая стартовая настройка, а точное значение следует выбирать измерением на нужных данных. Память: `O(n)` для буфера и `O(log n)` для стека вызовов.

## Задание 4.3 — Merge Sort односвязного списка без нового массива

`src/task4_3.cpp` использует **итеративное** слияние снизу вверх. Сначала сливаются соседние серии длиной 1, потом 2, 4, 8 и так далее. `split` разрывает связи после нужного числа узлов, а `merge` соединяет уже существующие узлы в правильном порядке. Значения не копируются в другой массив; новых узлов во время сортировки не создаётся. Локальный фиктивный узел в `merge` живёт на стеке только в одном вызове.

Время `O(n log n)`. Дополнительная память самой сортировки — `O(1)`: здесь нет рекурсии и нет массива. Создание исходного списка в `main` к этой дополнительной памяти не относится.

## Задание 4.4 — Merge Sort для Chunked List

`src/task4_4.cpp` хранит последовательность в односвязных блоках. Каждый узел содержит массив до `B` значений. `Cursor` хранит указатель на текущий блок и смещение внутри его массива; после последнего элемента блока он переходит к следующему блоку. Сортировка сливает серии длиной 1, 2, 4, ... в один дополнительный массив `buffer` размера `n`, затем последовательно записывает результат обратно в блоки. Чтение и запись идут по порядку, без поиска элемента с начала списка по индексу.

**Сравнение реализаций:**

| Структура и реализация | Время | Дополнительная память | Влияние констант |
| --- | --- | --- | --- |
| Массив, пункт 4.2 | `O(n log n)` | `O(n)` + стек `O(log n)` | Лучшее последовательное размещение элементов; обычно низкая стоимость доступа |
| Односвязный список, пункт 4.3 | `O(n log n)` | `O(1)` | Копировать значения не нужно, но каждый элемент требует перехода по указателю; память узлов разрозненна |
| Chunked List, пункт 4.4 | `O(n log n)` | `O(n)` | Внутри блока доступ последовательный; переходов между блоками примерно `n/B` на проход. Но реализация записывает каждый проход в буфер и обратно, поэтому её константа может превышать константу массива |

`B` влияет на практическое время: большой блок уменьшает число переходов по указателям и накладные расходы на узлы, но не меняет асимптотику. Таблица описывает именно реализации в этом проекте, а не любую возможную реализацию сортировки Chunked List.

## Задание 5.1 — хватит ли номеров в отеле

`src/task5_1.cpp` превращает каждое ненулевое бронирование в два события: прибытие `+1`, отъезд `-1`. События сортируются по дате; при равной дате отъезд ставится **раньше** прибытия. Последовательный проход считает занятые номера и запоминает максимум. Если максимум не больше `k`, ответ `YES`.

Это эквивалентно нахождению максимального числа пересекающихся интервалов бронирования. Сортировка `2n` событий стоит `O(n log n)`, проход — `O(n)`, память — `O(n)`.

## Задание 5.2 — гарантированно линейный Select

`src/task5_2.cpp` реализует median-of-medians. Элементы разбиваются на группы максимум по 5, каждая группа сортируется, её медиана переносится в начало текущего диапазона. Рекурсивно выбирается медиана этих медиан — опорный элемент `pivot`. Затем диапазон делится на три части: меньше, равно и больше `pivot`; поиск продолжается только в той части, где находится искомый порядковый номер. Трёхчастное деление корректно работает и с повторяющимися значениями. `k` во входе начинается с 1, внутренний индекс — с 0.

Группы по пять гарантируют, что с каждой стороны от `pivot` можно отбросить постоянную долю элементов. Рекуррентная оценка `T(n) ≤ T(⌈n/5⌉) + T(7n/10 + O(1)) + O(n)` даёт **`O(n)` в худшем случае**, в отличие от обычного Quick Select со случайным или фиксированным pivot. Малые диапазоны длиной до 32 сортируются вставками, что не меняет асимптотику.

## Задание 5.3 — минимальное суммарное ожидание пациентов

`src/task5_3.cpp` сортирует длительности приёма по возрастанию: короткие приёмы первыми. Если два соседних приёма имеют длительности `a > b`, перестановка `a,b` на `b,a` уменьшает ожидание второго пациента на `a-b`, не меняя ожидание пациентов после этой пары. Поэтому любое расписание с такой парой можно улучшить; оптимальное расписание не содержит убывающих соседних длительностей.

После сортировки `elapsed` хранит суммарную длительность всех уже проведённых приёмов. Перед очередным приёмом это время прибавляется к `total_wait`. Сортировка стоит `O(n log n)`, проход `O(n)`, память `O(n)`. При максимальных ограничениях сумма ожиданий может не поместиться в 32-битный `int`, поэтому используется `std::int64_t`. Для примера `5 1 3 2 4` оптимальный порядок `1 2 3 4 5`, ожидания `0+1+3+6+10=20`.

## Задание 5.4 — число пар с заданной суммой

`src/task5_4.cpp` сортирует различные значения и ставит два указателя по краям массива. Если сумма крайних равна `S`, найдена одна пара и оба указателя сдвигаются внутрь. Если сумма меньше `S`, левый элемент слишком мал и левый указатель увеличивается; если больше — правый элемент слишком велик и правый указатель уменьшается. Поскольку значения различны, одна найденная пара не может участвовать в другой паре с той же суммой.

Сортировка стоит `O(n log n)`, дальнейший проход — `O(n)`, память для массива `O(n)`; дополнительная память алгоритма после чтения зависит от реализации `std::sort` (обычно `O(log n)` стека). Пара индексов исходного массива учитывается один раз: сортировка меняет позиции значений, но не меняет число подходящих пар. Для чисел `1 2 3 4 5 6` и `S=7` ответ `3`.

## Задание 5.5 — Quick Sort с одним рекурсивным вызовом

`src/task5_5.cpp` выбирает медиану первого, среднего и последнего значений как `pivot` и разделяет диапазон на три части: `< pivot`, `== pivot`, `> pivot`. Это помогает на входе с большим числом повторений. **Меньшая** из двух внешних частей сортируется одним рекурсивным вызовом; большая обрабатывается продолжением цикла `while`. Поэтому глубина собственного рекурсивного стека — `O(log n)` даже при неудачных разбиениях.

Малые диапазоны до 24 элементов сортируются вставками. После слишком большого числа уровней разбиения используется сортировка кучей (`make_heap` + `sort_heap`), чтобы даже специально подобранный неудачный вход имел гарантированное время `O(n log n)`. Обычно работают разделения Quick Sort; дополнительный резервный алгоритм делает реализацию устойчивой к худшему случаю. Память собственного рекурсивного стека — `O(log n)`.
## Подробное рассуждение и трассировка алгоритмов

Ниже приведён разбор *почему* работает каждое решение. Под «инвариантом» понимается утверждение, остающееся верным после каждого шага цикла или рекурсивного вызова. В исходных файлах 4.1–4.4, 5.2 и 5.5 диапазоны вида `[left,right)` включают левую границу и не включают правую; в 5.2 внутренний диапазон `[left,right]` включает обе границы.

### 4.1. Инверсии: от проверки всех пар к подсчёту целыми группами

Инверсия — два **исходных** элемента с индексами `p<q`, но значениями `a[p]>a[q]`. Если проверять каждую пару отдельно, понадобится `n(n-1)/2` сравнений, то есть `O(n²)`. При слиянии двух уже отсортированных половин можно посчитать сразу несколько инверсий одним сравнением. Вызов `count_inversions(a,buffer,left,right)` обещает два результата: число инверсий на данном отрезке и отсортированное содержимое `a[left...right)`.

Инверсии делятся на три непересекающиеся группы: обе позиции в левой половине, обе в правой, одна слева и одна справа. Рекурсивные вызовы считают первые две группы. При слиянии указатель `i` стоит на наименьшем ещё не перенесённом элементе левой половины, `j` — аналогично правой. Если `a[i] <= a[j]`, левый элемент не образует инверсии ни с одним оставшимся правым: все они не меньше `a[j]`. Если `a[j] < a[i]`, правый элемент образует инверсию с **каждым** оставшимся левым: левая половина отсортирована, значит, все элементы с `i` до `middle-1` не меньше `a[i]` и строго больше `a[j]`. Поэтому прибавляется сразу `middle-i`.

Например, сливаем `[2,8]` и `[1,6]`. Для `1` прибавляем 2: пары `(2,1)` и `(8,1)`. Затем переносим `2`; для `6` прибавляем 1: пару `(8,6)`. Итого три перекрёстные инверсии. Каждый элемент переносится ровно один раз на данном уровне рекурсии. Уровней `O(log n)`, поэтому время `O(n log n)`, буфер `O(n)`. При миллионе элементов ответ может быть `499999500000`, поэтому нужен `std::int64_t`.

### 4.2. Merge Sort массива: инвариант слияния и один буфер

После рекурсивных вызовов обе половины `[left,middle)` и `[middle,right)` отсортированы. Инвариант цикла слияния: `buffer[left...out)` содержит в правильном порядке **все уже выбранные элементы** из обеих половин; `i` и `j` указывают на первые ещё не выбранные. Следующим в окончательном порядке может быть только меньший из `a[i]` и `a[j]`. Выбор меньшего и сдвиг соответствующего указателя сохраняют инвариант. Когда одна половина кончилась, остаток другой уже отсортирован и просто дописывается. Затем готовый отрезок возвращается из буфера в `a`.

При равенстве берётся левый элемент (`<=`), поэтому два равных элемента сохраняют исходный относительный порядок: сортировка **устойчива**. Если `a[middle-1] <= a[middle]`, максимальное число левой половины не больше минимального правой. Следовательно, все левые значения уже предшествуют всем правым, и копирование можно пропустить. На отрезке длиной до 32 сортировка вставками обычно дешевле из-за малого числа вызовов и простой работы с памятью; выбор 32 влияет на скорость в конкретной среде, но не на класс сложности. Буфер выделяется в `main` **один раз** и передаётся в рекурсию по ссылке, а не создаётся на каждом уровне.

В худшем случае на каждом из `O(log n)` уровней все `n` элементов участвуют в слиянии: `O(n log n)` времени. Дополнительная память — `n` элементов буфера и `O(log n)` кадров рекурсии. Если вход уже упорядочен, многие слияния пропускаются, но алгоритм всё равно должен прочитать данные.

### 4.3. Список: почему достаточно менять указатели

В односвязном списке нет быстрого доступа к `a[i]`, поэтому алгоритм обходит его последовательными сериями. В начале прохода ширины `w` каждая серия длиной не более `w` уже отсортирована. `split(left,w)` обрывает ссылку после первой серии и возвращает начало следующей; второй `split(right,w)` обрывает вторую. Теперь `merge(left,right,merged_tail)` соединяет существующие узлы в одну отсортированную серию длиной не более `2w`.

Инвариант внутри `merge`: цепочка после фиктивного `dummy` отсортирована; `tail` — её последний узел; `left` и `right` указывают на ещё не присоединённые отсортированные остатки. Берётся меньшая вершина из `left` и `right` и присоединяется после `tail`. Других новых узлов нет. `Node*& source` — ссылка **на один из указателей** `left` или `right`, поэтому присваивание `source = source->next` продвигает именно выбранную серию. После окончания одной серии остаток второй можно присоединить целиком. `dummy` — локальный временный узел, его адрес не остаётся в готовом списке: возвращается `dummy.next`.

Внешний проход соединяет результаты через `result_tail`; в конце все серии длиной не более `2w` отсортированы. Удвоение `w` повторяется до ширины не меньше `n`. Каждый проход трогает `O(n)` узлов, проходов `O(log n)`. Сортировка не выделяет массив и не создаёт новые узлы: дополнительная память `O(1)`. `main` отдельно выделяет `n` исходных узлов, а после вывода удаляет каждый из них.

### 4.4. Chunked List: логические серии поверх физических блоков

Данные физически распределены по блокам, например `[7,2,5] → [2,-1,9] → [0]` при `B=3`. Граница отсортированной серии может оказаться **внутри** блока: серии длины 2 здесь начинаются на позициях 0, 2, 4, 6, независимо от границ узлов. `Cursor` превращает пару `(указатель на блок, смещение внутри блока)` в способ последовательного чтения логической последовательности. `advance()` сначала сдвигается внутри блока, а на его конце переходит по `next`.

В начале прохода ширины `width` каждая логическая серия до `width` элементов отсортирована. Для очередной пары `left_count` и `right_count` ограничивают реальную длину серий концом списка. `left` и `right` — два курсора на первые элементы этих серий; `right.skip(left_count)` ставит правый курсор после левой серии. Цикл выбирает меньший текущий элемент и записывает его в `buffer`. Инвариант такой же, как при слиянии массивов: уже записанная часть буфера отсортирована и содержит ровно уже потреблённые элементы двух серий. После всех пар `buffer` содержит весь список, разбитый на более длинные отсортированные серии. Последовательная запись буфера обратно в блоки завершает проход.

Даже если `right_count == 0`, чтения через правый курсор нет: условие `j < right_count` сразу ложно. Каждый проход последовательно читает и записывает `n` значений, значит, стоит `O(n)`. Ширина удваивается `O(log n)` раз, время `O(n log n)`, буфер `O(n)`. Размер блока `B` влияет на число переходов между узлами и локальность памяти, но не меняет асимптотику. Это объясняет, почему сравнивать реализации лучше измерением, а не одной только записью `O(n log n)`.

### 5.1. Отель: почему максимум одновременных проживаний даёт ответ

Каждое бронирование занимает номер в полуоткрытом интервале `[arrival,departure)`. На приезде количество занятых номеров растёт на 1, на отъезде уменьшается на 1. После сортировки событий инвариант прохода: `occupied` равно числу бронирований, активных **после уже обработанных событий**; `maximum` равно наибольшей ранее достигнутой занятости. Если два события имеют одну дату, отъезд `-1` сортируется перед приездом `+1`: освободившийся утром номер можно отдать прибывающему в тот же день.

Для примера `hotel.txt` с двумя номерами даты 1–5 июня и 3–7 июня дают пик 2. Бронирование 5–8 июня не поднимает занятость до 3: сначала обрабатывается отъезд 5 июня, потом приезд. Поэтому вывод `YES`. Если в некоторый момент `maximum > rooms`, гостей в этот момент больше, чем номеров, и размещение невозможно. Если `maximum <= rooms`, в каждый момент хватает номеров; индивидуальный номер можно повторно использовать после отъезда. Сортировка `2n` событий требует `O(n log n)` времени и `O(n)` памяти.

### 5.2. Select: почему медиана медиан исключает плохой pivot

Цель `select_k` — получить значение, которое стояло бы на абсолютном индексе `k` после сортировки, **без сортировки всего массива**. В начале каждой итерации нужный элемент находится в текущем диапазоне `[left,right]`. Медианы групп по пять переносятся в начало диапазона; рекурсивно находится медиана этих медиан — `pivot`. После трёхчастного разбиения инвариант: `[left,less)` содержит элементы меньше `pivot`, `[less,greater]` равны ему, `(greater,right]` больше него. Поэтому по положению `k` можно безошибочно выбросить две ненужные части или сразу вернуть `pivot`.

Почему pivot достаточно хорош? В полной группе из пяти медиана не меньше трёх элементов группы и не больше трёх. Не менее половины групповых медиан не меньше медианы медиан, значит, не менее примерно `3n/10` исходных элементов не меньше `pivot`; симметрично не менее `3n/10` не больше него. Неполная последняя группа и одна пограничная группа меняют это лишь на постоянное число. Следовательно, если поиск продолжается, новый диапазон имеет размер не более примерно `7n/10 + O(1)`. На поиск pivot тратится `T(⌈n/5⌉)`, на группировку и разделение `O(n)`: `T(n) ≤ T(⌈n/5⌉)+T(7n/10+O(1))+O(n)`. Доли `1/5+7/10=9/10<1`, поэтому суммарная работа `O(n)` даже на худшем входе.

Трёхчастное разбиение также важно для повторений. Если искомый `k` находится среди элементов, равных `pivot`, ответ уже известен; не нужно снова искать среди одинаковых чисел. Пользователь задаёт `k` с единицы, а в массиве индексы с нуля, поэтому `main` передаёт `k-1`.

### 5.3. Пациенты: доказательство обменом соседей

Пусть к началу двух соседних приёмов уже прошло время `W`, а их длительности `a` и `b`, где `a>b`. При порядке `a,b` ожидания этих двух пациентов равны `W` и `W+a`. При порядке `b,a` они равны `W` и `W+b`. Второй вариант уменьшает сумму на `a-b>0`. Все пациенты после этой пары начнут ждать после общего времени `W+a+b` в обоих вариантах, поэтому их ожидание не меняется. Значит, соседнюю пару «длинный, короткий» всегда выгодно поменять местами.

Повторяя такие обмены, приходим к неубывающему порядку длительностей; более выгодного порядка быть не может, потому что любое нарушение порядка можно улучшить. После сортировки `elapsed` равен сумме длительностей уже обслуженных пациентов. Перед очередным приёмом именно `elapsed` нужно прибавить к `total_wait`, затем обновить `elapsed`. Для длительностей `5,1,3,2,4` порядок `1,2,3,4,5` даёт ожидания `0,1,3,6,10` и сумму `20`. Сортировка `O(n log n)`, проход `O(n)`, 64-битный счётчик предотвращает переполнение при больших ограничениях.

### 5.4. Пары с суммой S: почему можно сдвигать только один край

В условии PDF пропущено выражение, связывающее пару индексов с `S`; программа принимает трактовку `A[i]+A[j]=S` для `i<j`. После сортировки `left` и `right` ограничивают ещё не исключённые кандидаты. Если `a[left]+a[right]<S`, то `a[left]` **не может** составить нужную сумму ни с каким элементом между указателями: все они не больше `a[right]`, значит, их сумма с `a[left]` ещё меньше `S`. Поэтому `left` можно безопасно увеличить. Если сумма больше `S`, симметрично `a[right]` не может составить пару ни с одним оставшимся слева, и `right` уменьшается.

Если сумма равна `S`, пара найдена. Поскольку все значения различны, для `a[left]` нужное дополнение единственно: `S-a[left] = a[right]`. Для `a[right]` оно также единственно, поэтому оба указателя можно сдвинуть. Так ни одна подходящая пара не пропускается и не считается дважды. Сортировка стоит `O(n log n)`, проход указателей `O(n)`. Сортировка переставляет значения, но при различных значениях сохраняет число подходящих пар исходных индексов.

### 5.5. Quick Sort: инвариант трёх областей и предел глубины

Перед разделением выбирается `pivot` как медиана первого, среднего и последнего **значений**. Это снижает риск плохого разделения на простых упорядоченных входах, но само по себе не гарантирует хороший худший случай. Внутри цикла разделения диапазон имеет четыре части: `[left,less)` — меньше `pivot`; `[less,current)` — равно; `[current,greater)` — ещё не проверено; `[greater,right)` — больше. При элементе меньше опорного обмен с `a[less]` расширяет первую область. При большем обмен с `a[--greater]` расширяет последнюю, но `current` не сдвигается: пришедший справа элемент ещё нужно проверить. При равном увеличивается только `current`. Когда `current == greater`, неизвестных элементов не остаётся.

После разделения среднюю область сортировать не надо: все её элементы равны. Из двух внешних частей **меньшая** сортируется рекурсивно, а большая остаётся текущему циклу `while`. Поэтому вложенные рекурсивные вызовы каждый раз получают не больше половины элементов текущего диапазона, и глубина собственного стека не превосходит `O(log n)`. Например, если части имеют размеры 3 и 100, рекурсия получает 3, а цикл продолжает со 100.

Если число уровней разделения на одном пути становится слишком большим, код переключается на `make_heap` + `sort_heap`. Это сортировка кучей за `O(m log m)` для оставшегося участка размера `m`. Предел около `2 log₂ n` ограничивает суммарную работу разделений, а резервный алгоритм ограничивает цену плохих оставшихся участков; весь алгоритм имеет гарантированное время `O(n log n)`. Для участков до 24 элементов применяется сортировка вставками. Так сочетаются быстрый обычный ход Quick Sort, устойчивость к множеству равных значений и ограничение худшего случая.
